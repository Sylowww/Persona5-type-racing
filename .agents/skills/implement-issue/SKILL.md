# Implement Issue

1. Read the issue and relevant project requirements.
2. Inspect the existing code before making changes.
3. Identify affected components, services, database code and tests.
4. Reuse existing patterns and architecture.
5. Make the smallest change that fully satisfies the issue.
6. Do not refactor unrelated code.
7. Add or update tests for changed business logic.
8. Run lint, typecheck and relevant tests.
9. Fix failures caused by the implementation.
10. Summarize:
   - what changed;
   - files affected;
   - tests executed;
   - assumptions or unresolved requirements.

Never claim a test passed unless it was actually executed.
